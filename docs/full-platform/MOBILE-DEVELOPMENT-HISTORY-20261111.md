## 职责与连接通路（独立设计）

| 层 | 职责 | 不承担 |
|---|---|---|
| 服务端 | 模型与任务执行、工具运行、持久会话、权限裁决、配额、能力目录、操作结果及事件续接 | 键盘、选区等平台瞬态UI |
| 服务适配器 | 能力/查询/命令/订阅、鉴权接入、字段映射、错误归一与重连；可替换fixture与自有服务实现 | 业务组件布局、把失败当成功 |
| 客户端状态与投影 | 身份隔离、乐观待确认状态、修订与终态处理、内容投影、缓存与恢复协调 | 推测服务完成、覆盖服务端权威状态 |
| 原生组件 | 导航、输入、消息块、操作、审批、能力可用性和错误展示 | 直接调用供应商SDK、直接解释传输包 |
| 平台适配 | 键盘/IME、焦点、选区、手势、滚动、安全区、生命周期、用户选择文件与系统权限 | 任意本地执行、任意目录扫描 |

服务能力/快照/事件 → 服务适配器 → 身份及代次校验 → 页面状态/内容投影 → 原生组件。
用户操作 → 类型化动作 → 客户端校验/待确认呈现 → 服务适配器 → 服务端结果/事件。

组件本地状态（草稿、焦点、展开、滚动锚点）与服务状态（会话、消息、任务、权限）分别拥有。服务端权威不等于禁止客户端缓存或乐观呈现；必须明确待确认、拒绝、超时和恢复语义。

## 阶段一：先建立核心合同与可替换边界

先审计并复用已有参考合同/夹具，不另起一套同义schema。只定义首个核心页所需最小合同：

- 能力：标识、版本、适用账户/工作区/会话作用域、是否支持、是否可用、不可用原因及参数约束。能力目录不是服务端授权；每次操作仍由服务端裁决。
- 查询：会话列表/历史与能力快照；分页、空结果、权限失败、服务失败分别表示。
- 动作：新建会话、发送、停止、重试、编辑；定义客户端意图ID、服务请求ID映射、幂等键及作用域。
- 事件：接受、增量、替换/修订、完成、取消、失败；携带足够的账户/会话/消息/请求身份、订阅代次、顺序或恢复游标。具体字段须在实现合同中确定，不能宣称服务已支持。
- 未知能力与未知内容块：安全降级并保留解释，不能静默丢失或崩溃。
- 连接：连接/恢复中、离线、认证失效、不可恢复缺口；不能把断线等同生成结束。

交付：组件输入/输出表、服务adapter接口、身份/状态转换表、确定性fixture adapter。fixture通过同一接口驱动组件，不在UI中另写演示分支。网络接线未实施前明确标为fixture验收。

## 阶段三：服务能力驱动的扩展与真实服务验证

- 模型/配置控件从服务可用模型及参数约束投影，不把官方模型名称硬编码为真实服务能力。

交付：能力—控件—动作—事件映射矩阵、模块挂载/卸载规则、真实服务联调报告或具体阻塞。离线回放与真实联调分别验收。
