# 主框架交付整合：普通启动与恢复

本轮修复独立iOS宿主的交付缺口，不声称恢复了官方启动／账户实现。原页面、资源、手势与组件证据保持既有版本边界；没有扩展Android、其他侧栏包或实际服务。

## 已实现

- 普通无参数启动直接读取随应用打包的core能力目录，恢复明确选定的演示资料。首次无选择时使用独立`preview`资料；不再自动构造旧LocalHarness。
- `--host-preview=core --host-profile=<UUID或preview>`只保存版本与资料标识。Chat、认证、Remote及通知等27个源码文件从同一个启动owner读取配置；冲突资料参数、无效配置和不允许持久化的测试参数明确失败。
- 原来显式`--offline-fixture`的定向检查仍是临时环境，不读取／覆盖日常资料选择，也不继承core其他成功回放能力。
- 不持久化命令行的语言、外观和失败夹具；应用继续跟随系统／用户已有设置。
- 保存账户／资料作用域内的一级页面，重启后从真实父容器打开；Chat／Work模式、当前会话、草稿以及Remote草稿由原有独立存储恢复。通知显式导航优先于旧一级页面。
- 配置失败提供说明、重试与显式默认资料恢复。原指针先保留，已有会话和资料文件不删除；坏的页面位置文件本次不覆盖。
- 启动脚本支持无参数日常启动，以及显式选择core资料；core配置现同时属于应用资源，不再只是UITest资源。
