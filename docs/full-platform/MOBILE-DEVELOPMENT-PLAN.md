## 产品目标

建设可二次开发的 iOS/Android 原生前端：依据官方代码、资源、制品和版本明确的视觉参考恢复组件与交互，通过独立合同映射自有服务端能力。核心AI、任务、工具执行与业务权限在服务端，前端不建设本地执行器。

保真与适配是两个独立门槛：官方风格/原生交互一致，不证明服务接通；服务合同通过，不证明界面恢复。官方293为移动实现证据基线，较新截图另列版本未知，第三方只作辅助参考。官方实现观察与下述独立产品设计不混写。

## 职责与连接通路（独立设计）

| 层 | 职责 | 不承担 |
|---|---|---|
| 服务端 | 模型与任务执行、工具运行、持久会话、权限裁决、配额、能力目录、操作结果及事件续接 | 键盘、选区等平台瞬态UI |
| 服务适配器 | 能力/查询/命令/订阅、鉴权接入、字段映射、错误归一与重连；可替换fixture与自有服务实现 | 业务组件布局、把失败当成功 |
| 客户端状态与投影 | 身份隔离、乐观待确认状态、修订与终态处理、内容投影、缓存与恢复协调 | 推测服务完成、覆盖服务端权威状态 |
| 原生组件 | 导航、输入、消息块、操作、审批、能力可用性和错误展示 | 直接调用供应商SDK、直接解释传输包 |
| 平台适配 | 键盘/IME、焦点、选区、手势、滚动、安全区、生命周期、用户选择文件与系统权限 | 任意本地执行、任意目录扫描 |

服务能力/快照/事件 → 服务适配器 → 身份及代次校验 → 页面状态/内容投影 → 原生组件。
用户操作 → 类型化动作 → 客户端校验/待确认呈现 → 服务适配器 → 服务端结果/事件。

组件本地状态（草稿、焦点、展开、滚动锚点）与服务状态（会话、消息、任务、权限）分别拥有。服务端权威不等于禁止客户端缓存或乐观呈现；必须明确待确认、拒绝、超时和恢复语义。

## 阶段一：先建立核心合同与可替换边界

先审计并复用已有参考合同/夹具，不另起一套同义schema。只定义首个核心页所需最小合同：

- 能力：标识、版本、适用账户/工作区/会话作用域、是否支持、是否可用、不可用原因及参数约束。能力目录不是服务端授权；每次操作仍由服务端裁决。
- 查询：会话列表/历史与能力快照；分页、空结果、权限失败、服务失败分别表示。
- 动作：新建会话、发送、停止、重试、编辑；定义客户端意图ID、服务请求ID映射、幂等键及作用域。
- 事件：接受、增量、替换/修订、完成、取消、失败；携带足够的账户/会话/消息/请求身份、订阅代次、顺序或恢复游标。具体字段须在实现合同中确定，不能宣称服务已支持。
- 未知能力与未知内容块：安全降级并保留解释，不能静默丢失或崩溃。
- 连接：连接/恢复中、离线、认证失效、不可恢复缺口；不能把断线等同生成结束。

交付：组件输入/输出表、服务adapter接口、身份/状态转换表、确定性fixture adapter。fixture通过同一接口驱动组件，不在UI中另写演示分支。网络接线未实施前明确标为fixture验收。

## 阶段二：官方风格 iOS 核心页闭环（当前首个产物）

恢复顺序（用户最新调整）：空白首页与顶栏 → 紧凑/聚焦输入区与原生键盘 → 侧栏与设置页 → 主视觉验收 → 消息宿主及内容专项。消息重要但后置集中处理，现有状态合同保留，本批不扩展消息解析或渲染。

复用已有官方资产、可执行模块和已核实规则；REA只解决当前组件的具体阻塞。必要的独立原生实现必须标来源和缺口，不用第三方风格替代官方目标，也不等待特殊语音/草图分支全部复原。

页面必须走完整通路：加载能力/历史 → 空白或会话页 → 输入/发送 → pending/accepted → 内容更新 → 停止/完成/失败 → 切换与恢复。停止按钮发出意图后显示待确认状态，不能直接伪造服务端取消完成。

交付：可构建的iOS模拟器产物、组件接线图、同配置画面和操作记录。沿用 IOS-CORE-PAGE-ACCEPTANCE 的 CORE-01—08；先交付普通聊天闭环，其余模式/功能保留在总范围与未验收清单中。

## 阶段三：服务能力驱动的扩展与真实服务验证

- 模型/配置控件从服务可用模型及参数约束投影，不把官方模型名称硬编码为真实服务能力。
- 附件前端负责选取、预览、上传状态；服务负责解析、处理和引用。麦克风采集等仅在能力和系统权限明确时接入，不自动引入本地推理。
- Remote/工作模式负责资源选择、任务/线程呈现、发送/取消、审批和产物查看；执行、项目访问及权限在服务端。移动端不运行CLI或本地被控端。
- 资料库、语音、图像、分享等作为按需第一方模块；核心聊天不依赖这些模块启动。不建设任意代码插件运行时。
- 测试服务地址、鉴权与合同版本明确后接入adapter，仅用合成数据。当前不假定自有服务已经具备这些接口，不要求本轮建设服务端。

未接服务的已恢复入口呈现明确不可用/未连接原因；按产品配置决定隐藏或禁用，不能伪造成功。审批结果按资源/请求/审批身份定域，客户端点击不能取代服务端执行授权。

交付：能力—控件—动作—事件映射矩阵、模块挂载/卸载规则、真实服务联调报告或具体阻塞。离线回放与真实联调分别验收。

## 验收与首批行动

| 维度 | 必须验证 |
|---|---|
| 原生保真 | 版本/来源明确的布局、主题/语言、键盘/IME、选区、菜单、滚动与恢复；缺视觉参考标未验收 |
| 能力映射 | 支持/不支持/暂不可用/权限拒绝/能力变化；未知能力不破坏核心页 |
| 消息合同 | A→B→A、并行输出、旧订阅、迟到/重复/乱序、正文修订、取消确认与历史合并 |
| 可替换性 | 同一页面不改组件即可切换fixture与一个实现既定合同的服务adapter；不承诺任意兼容后端直接接入 |
| 清理与恢复 | 会话/账号/模块切换时定域退订，重连获取快照/游标，草稿/阅读位置保留，不清理其他会话 |
| 安全边界 | 凭据不进入组件公共状态/日志，跨账户隔离；权限在服务端裁决；不连接官方服务或真实聊天 |

首批按顺序执行：审计现有合同/宿主直连点 → 抽取核心服务adapter与fixture → 连接完整iOS页面并恢复有证据的可见差异 → 模拟器验收并留下预览。不会为了合同整洁先搭通用插件框架，也不会为了界面可运行把业务执行搬回手机。

每批报告：实际界面变化、连接的能力与合同、官方/独立实现来源、已过与未过验收、下一具体阻塞。默认不提交/推送/发布，保护原件，沿用构建保留与附屏预览规则。
