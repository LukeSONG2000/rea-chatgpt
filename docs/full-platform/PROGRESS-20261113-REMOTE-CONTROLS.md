## iOS：智能体动作贯通到现有任务页

实际取证闭合了原智能体面板的分组滚动父容器、行回调完整Subagent载荷，以及bottom parent注入ThreadViewAction的路径。原最终动态handler中的host／thread映射仍未知，不能直接把agent.id当线程ID，也不能把原来的合成说明sheet称为官方目的地。

现在接口为：面板行 → 完整agent及账户／父任务／session／revision请求 → 显式optional目标提供方 → host／thread／title → 现有任务消息页 → 子任务独立输入与返回。请求与当前完整载荷、账户、订阅／编写代次及修订不匹配时不接受目标；未知、不可用和自指向目标不猜测。目标提供方的映射和本地native push是独立前端接口／宿主适配，不是已恢复的原RPC或转场。

离线provider为已知合成agent给出不同的子任务ID，先接受初始合成history再发布导航；已有journal不重种。父子任务各自保留草稿、消息及配置；子任务可继续发送合成输入，返回后父草稿不被清空。child不继承父fixture的Goal／智能体能力。没有映射时仍提供可返回的能力说明。

## Android

已补任务／资料／host-thread定域的当前配置；模型、思考力度和速度按显式离线能力选择，权限只有只读／默认。当前选择与已接受请求／排队intent的配置分开，后续选择不能改写历史。合成回放消费捕获的配置，不表示真实模型或权限已经生效。

运行中Queue／Steer与Stop分别接通，操作捕获具体request，旧按钮不能停止或引导后继请求。队列可取消／显式启动，支持原输入框内纯文本编辑：取消／离页保留原草稿，提交精确匹配task、pending ID和revision，在同一行替换，失败保留旧队列和编辑内容。queue转turn先原子保存，保留原配置、顺序和独立草稿。

修复两处队列边界：retry换request不能令旧queue永远无法手动恢复；新请求完成不能误发停止／重启前的旧queue。现在自动出队只消费同一continuation来源链，独立重试／新请求不自动继承旧链；显式恢复会核对历史已接受配置。

Goal可本地创建／暂停／恢复／清除；用量是明确的本地只读统计，智能体当前提供空／未接详情状态，没有虚构运行管理。完整agent到child目标的对应导航接口仍缺。
