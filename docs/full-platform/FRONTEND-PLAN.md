# 当前实施计划：桌面/Web 与移动端两条主线

## 当前首要目标：官方核心页完整纵向链路（2026-11-05，最新指示）

用户明确撤回第三方主基线方向。先打通官方聊天核心页的入口、身份/状态、布局、内容投影、原生渲染、动作回写及清理恢复；外围页面与第三方工程扩展暂停。第三方只保留辅助参考价值，当前可运行预览保持供用户体验。

执行入口：[核心链路审计与验收](IOS-OFFICIAL-CORE-CHAIN.md)。旧原生宿主是接线载体，不自动认定为官方恢复；逐段替换未经证明的实现，不用新的近似界面替代取证。先交付一个可运行、来源明确、状态完整的核心页，再扩展页面和独立核对 Android。桌面/Web 既定方向、前端范围与云端执行边界不变。

## 移动端当前目标（2026-11-05 最新确认）

面向后续二次开发，恢复官方风格与原生交互的前端，并建立可替换的服务适配边界。核心能力在服务端，前端负责能力呈现、用户意图、事件投影和平台交互；不以逐函数复原官方内部实现作为交付目标。完整实施顺序与验收门槛以 [移动端二次开发适配计划](MOBILE-DEVELOPMENT-PLAN.md) 为准。

第三方优先、完整本地执行器及穷尽反编译等旧执行顺序均不再生效，历史证据保留。官方核心页纵向链路仍为第一交付，但须同时闭合“服务合同 → 状态投影 → 原生页面 → 用户动作 → 服务适配器”；离线夹具用于验证合同，不代表真实服务接通。

## 目标与边界

桌面与 Web 是同一前端产品方向：共享对话核心、状态语义、内容模型及组件合同，按需提供第一方功能模块。执行端面向云端；前端负责显示、交互、订阅与恢复。Mac 是桌面主验收渠道，Windows 独立验收；浏览器单独验收，不用 Electron 结果代替。

移动端保持独立原生主线，iOS/iPhone 主验收、Android 交叉验证。优先共享合同和测试向量，不把桌面 renderer 或 WebView 当作移动原生恢复。

原桌面 renderer 浏览器工程作为恢复验证入口；最终是否整体复用该 renderer，由依赖、可拆分性和性能证据决定，不预先绑定。官网 Web 仍是独立参考制品，未闭合的入口与版本证据保留为缺口，不用桌面资源证明官网一致，也不作为统一前端合同工作的前置阻塞。

## 主线一：桌面端 + Web

沿用既定统一前端方向；以下功能分层和桌面/Web 批次不因移动端优先而扩张。

### 功能分层

| 层 | 范围 |
|---|---|
| 必备核心 | 新建/发送/流式/停止/重试/编辑，会话列表与搜索，Markdown/代码/表格/附件呈现，复制，基础文件选择上传下载，草稿，断线和历史恢复，语言/主题，明确的错误状态 |
| 按需模块 | 云端任务/Remote，审批，项目与资料库高级管理，语音，图像生成/编辑，复杂文件预览，代码差异和产物查看，连接器，分享协作，通知，高级模型配置 |
| Web 明确不接 | 本地 AI/CLI/终端/进程与工具执行，本机 Git/Worktree/环境管理，任意本地路径访问，系统配置及凭据读取，设备扫描/SSH/隧道管理，系统菜单/托盘/全局快捷键，完整 IDE，桌面内部调试页 |

桌面保留窗口、菜单、焦点、剪贴板、用户选取文件等必要平台适配；当前同样不建设本地 AI 执行或本地执行环境。浏览器的输入法、剪贴板权限、用户选择文件、下载和有限草稿缓存属于基础交互，不被“本地能力不接”误排除。

“插件式”指可选、延迟加载、能力驱动的第一方模块；不建设第三方插件市场、任意代码下载或通用插件运行时。核心聊天不能依赖可选模块才能启动。没有服务能力时隐藏入口或明确显示不可用，不能静态按钮伪装成功。

## 两条主线共用的组件连接通路

用户操作 → 组件动作 → 服务适配器 → 云端查询/命令。
云端事件 → 作用域与身份校验 → 状态更新 → 内容投影 → 组件渲染。

每个核心组件和模块必须记录：

- 来源平台/版本、摘要、文件/符号；官方观察、推断、独立设计分别标注。
- 输入数据、稳定身份、能力与权限声明、加载/空/错误/完成状态。
- 动作、查询、命令、订阅及响应；取消、失败和幂等语义。
- 账户/会话/消息/请求/订阅代次/修订的归属；Remote 另含主机/连接/线程/审批请求作用域。
- 挂载、解绑、切换、迟到事件、重连、历史合并、草稿与阅读位置恢复。
- 平台能力依赖、模块加载/卸载、缺少能力时的呈现和验证用例。

审批 UI 只提交绑定具体请求的决定；权限检查及执行由服务负责。模型凭据不进入前端。现有 harness/owner 保留为隔离夹具，官方合同、建议云端合同与夹具协议分开；不修改生产 API。

## 主线一实施批次

1. **盘点与连接矩阵**：列出桌面/Web 核心组件、入口、状态 owner、服务调用和精确断点；同步近期桌面输入布局、语言、设置修复的证据。交付逐项差异与来源表，不声称已完成代码共用。
2. **核心对齐**：按源码恢复两端初始化和接线，统一可共享的身份/事件/内容语义，保留平台适配。优先聊天、列表/搜索、输入/阅读、草稿和历史恢复；每条链使用相同夹具分别验收。
3. **按需模块合同**：先闭合云端任务/Remote 线程正文、订阅与历史，再按实际需求接资料库、预览、语音、图像等。执行由确定性服务夹具模拟，不为前端验收新建执行器。模块必须能独立加载、失败和清理。
4. **浏览器减重与跨端验收**：首屏只加载当前会话所需代码/数据；高级模块延迟加载，历史分页，附件按需下载，后台会话不保留完整页面树。验证多标签协调、有界缓存和独立平台行为。
## 主线二：移动端原生前端与服务能力映射

按 [移动端二次开发适配计划](MOBILE-DEVELOPMENT-PLAN.md) 推进：先定义能力/动作/事件/组件合同，再恢复并接通 iOS 核心页，用确定性服务适配器完成整页验收，随后接自有测试服务并独立实现 Android。官方源码和制品是界面与交互依据，不把官方私有服务结构作为自有后端必须复制的约束。

共享合同、测试向量和可验证的纯状态逻辑；键盘、焦点、选区、手势、安全区、滚动执行和平台生命周期分别保留。现有 [跨平台证据矩阵](MOBILE-SHARING-MATRIX.md) 继续记录官方事实，与我们的共享方案分开。

## 验收与交付

- 桌面与浏览器分别覆盖发送/取消/错误/重试、A→B→A、并行输出、旧订阅/迟到/重复/乱序事件、正文修订、断线与历史恢复。
- 验证长文本/代码/宽表格/混合内容、IME、选区/复制、滚动锚点和用户拖动优先；语言遵循系统/浏览器并支持显式覆盖。
- 检查模块关闭/卸载后订阅释放，权限错误不显示为空结果，单云端资源故障不影响其他资源。
- 测量首屏可交互、输入延迟、长会话内存、解析/布局/帧耗时和模块加载成本；先记录基线再确定预算，不以包大小或定时器代替性能验收。
- 完成要求是前端通路与交互闭合，不要求本地 AI/工具执行。服务未实现时，明确状态和合同、可复用夹具必须齐备；不能声称真实云端集成通过。
- 每批交付来源证据、连接合同、源码改动、两端验证结果、精确缺口。原包和历史证据保留，不提交/推送/发布；沿用构建保留和附屏预览规则。
